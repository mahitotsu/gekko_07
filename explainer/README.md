# 解説：OAuth Token Exchange と AI エージェントの認可

このフォルダは、[gekko_07](../README.md) の内容を読むために必要な**背景知識を、初めての方にも分かりやすく解説する**ためのものです。

gekko_07 は、「OAuth 2.0 Token Exchange をマイクロサービスに横断的に組み込み、AI エージェントの実行権限を認可基盤の側で抑える」という設計を、金融の不正検知・口座凍結解除というシナリオで実際に動かして確かめた参照実装です。ただ、その前提となる仕様——Token Exchange（RFC 8693）、スコープと audience、送信者拘束（DPoP / RFC 8705）、そして AI エージェントに「身元」と「権限」をどう与えるか——は、なかなか込み入っています。そこを飛ばしてしまうと、「何を確かめたのか」が伝わりにくくなってしまいます。

そこでこのフォルダでは、**OAuth の基礎から出発して、これらの難しいところを一つずつ**、gekko_07 の実装を実例に使いながら、丁寧に説明していきます。読み終えていただくと、[docs/](../docs/) 配下の設計文書が「なぜそう作ったのか」まで含めて読めるようになるはずです。

## 対象読者

- OAuth 2.0 を名前は聞いたことがあるけれど、Token Exchange や AI エージェントの認可は初めて、という方
- マイクロサービスに AI エージェントを組み込もうとしていて、権限の設計に不安がある方
- 「トークンを渡す」だけでなく、「渡した先で本当に権限が絞れているか」を確かめたい方

特別な前提知識は要りません。必要な概念は、その都度説明していきます。
