# ADR 0011: シナリオを「AI支援による口座凍結解除」に変更（凍結は自動検知エンジンが実行）

- **Status**: Accepted
- **Date**: 2026-09-15
- **Supersedes**: [ADR 0001](0001-scenario-fraud-detection-with-agent-assist.md)

## Context

[ADR 0001](0001-scenario-fraud-detection-with-agent-assist.md)は「AIエージェントが口座凍結を提案し、アナリストが確認の上で凍結を確定する」というシナリオを採用していた。しかし、このシナリオにはリアリティの欠如という問題がある。

実際の不正検知業務では、疑わしい取引の**ブロック（凍結）はルールベース・リアルタイムスコアリングによって機械的・即時に行われる**のが通常であり、被害拡大を防ぐために人間やAIとの対話を待つ余裕はない。逆に、**凍結の解除**（誤検知の疑いがある口座を業務に復帰させる判断）は、根拠の整理・説明責任が伴う調査業務であり、「AIが根拠を整理して提案し、人間が最終確認する」という構造と自然に噛み合う。ADR 0001のシナリオは、この非対称性を反映できていなかった。

なお、ADR 0001が実演したかった5要素（マイクロサービスとAIエージェントの連携、一部のマイクロサービスがMCPサーバーと通常のマイクロサービスの両方から利用される、業務属性に基づくアクセス制御、AIの支援を受けつつ人間の決定論的操作で確定、事後監査可能性）自体は変わらず有効であり、今回の変更はドメイン内での「どちらの操作を人間の確定制に置くか」の見直しにとどまる。着手前の設計段階（未実装）でのピボットのため、実装済みコードへの影響はない。

## Decision

シナリオを次のように変更する：**口座の凍結は`fraud-detection-engine`（不正検知エンジン）が取引パターンを監視し自動的に実行する。AIエージェント（`fraud-agent`）は、凍結済み口座の凍結理由・取引履歴を分析し、誤検知の疑いがあれば凍結解除を提案する。凍結解除の実行はアナリストがUIで行う決定論的操作でのみ確定する。**

- `payment-service`を廃止し、`fraud-detection-engine`に置き換える。旧payment-serviceが担っていた「account-serviceがMCPサーバー経由（AI）と通常のマイクロサービスの両方から利用される」という対比構造、および「機械間認証（client_credentials）はユーザー委任チェーンに参加せず業務属性チェックも通らない」という設計上の見せ場は、fraud-detection-engineがそのまま引き継ぐ（`account:freeze`スコープで機械間認証によりaccount-serviceへ凍結を依頼する）
- `account-service`の実行系スコープを次のように再配置する：
  - `account:freeze`（機械間認証、`fraud-detection-engine`のみに付与）：自動検知による即時凍結。業務属性チェックなし
  - `account:unfreeze`（人間専用、`frontend`のみに付与）：凍結解除の実行。不可逆・高リスクな操作として、実行時にanalyst-attribute-serviceへ再照会し業務属性を再検証する（多層防御）
- AIエージェント（`fraud-agent`）は凍結解除の提案（記録）までの権限のみを持ち、解除の実行権限は一切持たない（`account:unfreeze`スコープをKeycloak側で一切付与しない設計は維持）

## Consequences

- 「凍結は自動・即時、解除は人間の判断」という構造は、実際の不正対策運用（自動ブロック→誤検知レビュー→解除）に近く、ドメイン知識なしでも直感的に伝わるリアリティを保ったまま、以前より実務に即したシナリオになる
- 凍結解除も「誤って解除すれば被害が継続する」という意味で不可逆・高リスクな操作であり続けるため、ADR 0001が狙っていた「AIには実行権限を持たせない」という設計思想の説得力は損なわれない
- AML/SAR的な監査要件（誰が何を根拠に何を確定したか）は、凍結の自動実行記録と凍結解除提案・確定の記録という2種類の監査対象に分かれ、architecture.md §9の監査設計とより自然に結びつく
- 影響範囲：requirements.md（目的の記述、BR2・BR3・BR5〜BR8）、architecture.md（表1・表2・表4・表5、§2・§4・§5・§8・§9、実行時シナリオ節）、services.md、README.md、および該当するKubernetesマニフェスト（realm-configmap.yaml等）を本ADRに合わせて更新する
