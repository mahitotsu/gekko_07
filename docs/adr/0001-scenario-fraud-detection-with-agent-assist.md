# ADR 0001: シナリオにAIエージェント支援付き金融不正検知・口座凍結を採用

- **Status**: Accepted
- **Date**: 2026-09-13

## Context

gekko_07で実演したい要素は次の5点だった。

- マイクロサービスとAIエージェントの連携
- 一部のマイクロサービスがMCPサーバーと通常のマイクロサービスの両方から利用される
- そのマイクロサービスがユーザーの識別情報から業務属性を取得しアクセス制御を行う
- AIエージェントの支援を受けつつ、最終判断は人間の決定論的な操作で確定する
- 一連の操作を事後に監査できる

これを乗せるドメインとして、以下を候補に検討した。

1. gekko_05の受発注ドメイン（Order/Inventory/Warehouse/Employee）をそのまま拡張する
2. 金融の不正検知・口座凍結を新設する
3. 医療の臨床意思決定支援を新設する

検討の結果、gekko_05の資源（コード・ドメイン）の再利用は方針として採用しないことにした（理由は本ADRの対象外。ユーザー判断）。医療は「AIが提案し人間が確定する」構造は満たすが、説得力を持たせるには薬剤相互作用・用量など医療ドメインの作り込みが必要で、アーキテクチャの実演という本題から外れた労力がかかる。

## Decision

**金融の不正検知・口座凍結**をシナリオに採用する。

- `account-service`（口座・取引データ）を、MCPサーバー経由（AIエージェント）と通常のマイクロサービス（`payment-service`）の両方から利用される共有サービスとする
- `account-service`は呼び出し元アナリストの業務属性（担当地域・権限レベル）を`analyst-attribute-service`から取得し、アクセス制御を行う
- AIエージェント（`fraud-agent`）は取引パターンを分析し口座凍結案を提案するのみで、凍結の実行権限を持たない（Keycloakのスコープ設計で強制する。詳細はarchitecture.md）
- 口座凍結の実行はアナリストがUIで行う決定論的操作でのみ確定する

## Consequences

- 「口座凍結」という不可逆・高リスクな操作を題材にすることで、「AIには実行権限を持たせない」という設計思想がドメイン知識なしでも直感的に伝わる
- AML/SAR的な監査要件（誰が何を根拠に何を確定したか）と自然に結びつくため、監査基盤を作り込む動機付けが強い
- gekko_05のコード資産は再利用しないため、全サービスを新規に実装する必要がある（言語構成は別途決定。backlog.md参照）
